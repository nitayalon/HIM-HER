## 9. Anomalies and places where the code disagreed with the brief

1. **Not JAX** (rule 5 n/a). Everything is plain Python/NumPy objects. New code follows the existing style, and seeds are parallelised with `multiprocessing`. A full 200-seed condition × method sweep takes about 35 s on 12 workers.
2. **Test count.** The suite had 150 tests: 143 committed plus 7 in the untracked `tests/test_bocd_bayes.py`. It is now 206, all passing. The untracked BOCD files were left untouched and not committed.
3. **`him_window` ≡ `full`.** HH-R's HER buffer is created with `maxlen = cascade.window = 20` (`hh_agent.py`; its docstring explains this is deliberate). The buffer and HIM's history are therefore the same last 20 transitions, so the brief's `full` ("current HH-R behaviour") already *is* the HIM window. The 200-seed runs and a test confirm bitwise-identical results. The brief's hypothesis — that replay includes pre-switch transitions — still holds, because the HIM window itself straddles the switch (§5).
4. **`post_detection` definition used.** Replay starts at the first round of the uninterrupted run of detected rounds that ended in this acceptance; a new run starts after each acceptance. It is capped at the 20 transitions in the buffer. Most acceptances occur on the first detected round, so this replays a median of 1 transition (the current one).
5. **Brief premise vs data (Within-library).** The brief says "a policy for the reused model already exists" in Within-library. In the 20-seed diagnostic, the first post-switch acceptance was **never** M_R. It was a merge in 13/20 seeds, a construct in 4 and a reuse of a different model in 3, at a median of 5 rounds after the switch. Only 4 of 61 post-switch acceptances were M_R. Over 200 seeds the paper's own counts show only 0.83 reuse acceptances per Within-library episode, against 2.2 merge and 1.03 construct.
6. **"m1 control" naming.** The code has no condition called "m1 control". I mapped it to `outside_library_switch_m1` (m1 = (0.1, 0.5), the midpoint of M_L and M_C, so representable by merge). The brief's "m2 outside-library" is `outside_library_switch_m2` (0.2, 0.8). Please check that this is the intended mapping.
7. **"Every incremental search step" for merge/construct.** Construct is closed-form (one candidate). Merge is a single argmax over all library pairs × 21 mixing weights, i.e. up to ~5,000 grid points per round, not an incremental search. I therefore logged **every HIM-evaluated candidate** (reuse/merge/construct, in order, across consecutive detected rounds). `step_index` counts them within a detection run and resets after an acceptance. That is the m2 trajectory in §7.
8. **ε schedule timing.** A detection in round t is only known after round t's action, so the first action under the reset ε is round t+1, with ε = ε₀·2^(−1/50) ≈ 0.148. Episode start gives exactly ε₀ at t = 0. `eps_reset` events are logged at t = 0 and at every detection, whether or not a revision follows.
9. **Discounting / windowing granularity.** CB conditions per context and decays nothing per step. So WB keeps a 20-observation window **per context**, and DB discounts only on an observation **in that context**. Both mirror CB's prior (Beta(1,1)), its greedy rule (R iff θ_x > 0.5, ties → L) and its lack of exploration. WB with a window ≥ T and DB with γ = 1 reproduce CB bitwise (tests).
10. **Identical baseline rows.** These are expected from the code, not bugs.
    - FB ≡ OB in Stationary and Within-library: OB adds the last true model, which is already in L₀ there.
    - In Stationary, DB-0.95 and DB-0.98 (and nearly WB/DB-0.90/CB) choose identical actions: all quickly settle on "always L".
    - All HH-R/HH-A variants share the cascade trajectory per seed: detection and HIM only see the environment's draws.
11. **VOC.** No VOC check exists (`AlwaysProceedVOC`), so `n_voc_declined` is 0 by construction.
12. **Pre-existing curiosity, not changed.** `run_episode` seeds the game RNG and the HH agent's ego RNG with the same integer (`default_rng(seed)` twice). They are separate generators producing the same stream: e.g. at t = 0 the ego's exploration draw equals the game's context draw. The streams desynchronise immediately afterwards because the draw counts per round differ.
13. **Stale comments, not changed.** `library.py`'s docstring says rejected candidates enter the library; they do not. A comment in `scripts/run_experiments.py:56-60` says HIM is "scoped to the incumbent only"; it compares against the full pool. See the Task E audit.
14. **`per_step` storage.** Full per-step logs exist only for the 10-seed regression, the 20-seed Within-library diagnostic and the 5-seed smoke tests. The 200-seed runs use `log_level=events`, as the brief specifies.
